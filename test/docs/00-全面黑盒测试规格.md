# Gulugulu 全面黑盒测试规格

版本：1.0

建立日期：2026-08-07

适用对象：Gulugulu Windows、macOS、Linux 的可安装/可运行版本，以及 Steam 与非 Steam 分发形态

## 1. 目标

本规格用于反复执行项目级全面测试，目标不是证明“脚本绿色”，而是证明玩家在真实安装、升级、离线、故障、极限输入、多语言和长期运行条件下仍能安全、可理解地游玩。

每轮必须回答五个问题：

1. 当前测试对象与上次相比变了什么？
2. 当前机器、账号、工具和时间允许我们真正验证什么？
3. 玩家主循环、数据与外部依赖是否可用且可恢复？
4. 21 种语言下，玩家看到的语义与布局是否正确？
5. 哪些是应立即修复的缺陷，哪些只能留档等待审阅？

## 2. 黑盒边界

### 2.1 允许使用

- 正式安装包、Steam 分支或明确冻结的候选包。
- 玩家可见 UI、托盘菜单、系统通知、文件选择器、安装/卸载界面。
- 操作系统任务管理器、网络开关、端口占用、文件权限、磁盘配额、时区和显示设置。
- Steam 客户端正常玩家入口、测试账号和沙盒库存。
- Codex/Claude 正常安装、未安装、退出、日志不可读等用户可遇到的状态。
- 自动点击、键盘输入、截屏、录像、OCR、性能采样和网络故障注入。
- 通过合法游玩形成并脱敏保存的阶段性存档；允许复制、冲突、截断或损坏这些测试副本。

### 2.2 黑盒发现阶段禁止使用

- 阅读产品源码来推导“它本来就会这样”。
- 直接调用内部命令、调试路由或修改内存来制造“已通过”状态。
- 直接编辑数值配置、存档字段或 Steam 物品定义来绕过玩家前置。
- 用浏览器组件测试替代 Tauri 原生窗口、托盘、全局键盘钩子或 Steam 真机结果。
- 用单元测试、构建成功或静态翻译检查宣称玩家路径已通过。

### 2.3 修复阶段

黑盒失败必须先保存复现步骤、前后状态和证据，再进入源码定位与修复。修复完成后生成新的候选包，从干净测试状态重跑原用例、相邻用例和主循环冒烟。不得用源码判断替代复测。

## 3. 缺陷分流与修改权限

| 类型 | 例子 | 默认处理 |
| --- | --- | --- |
| FUNC 功能/规则错误 | 无法购买、融合重复扣除、按钮显示成功但状态没变 | 立即复现、修复、黑盒复测 |
| STAB 稳定性/恢复 | 崩溃、卡死、重启无法恢复、端口冲突导致不可启动 | 立即复现、修复、黑盒复测 |
| DATA 数据/资产安全 | 存档丢失、云冲突无备份、Steam 材料重复消耗 | 立即停止扩大影响，修复并做恢复证明 |
| DEP 依赖降级 | 没有 Codex/Claude、Steam 离线、WebView 缺失时游戏不可用 | 立即修复或提供明确可恢复降级 |
| L10N 语义/文化错误 | `left` 被译成方向、主客体/否定/数量/货币含义错误 | 立即修复并检查所有相关语言与同屏上下文 |
| VIS 视觉/布局错误 | 文本超宽、遮挡、RTL 乱序、按钮不可达、窗口变形 | 立即修复并做语言/分辨率回归 |
| PRIV 隐私/安全 | 记录实际按键内容、上传非预期文件、UGC 越权 | 立即阻断发布并修复 |
| NUM 数值合理性 | 价格、成长速度、概率、掉落量不合理 | **只记录 `REVIEW-NUM`，不得自行修改** |
| UX 体验顺畅度 | 节奏拖沓、反馈太弱、步骤过多、信息密度不舒服 | **只记录 `REVIEW-UX`，不得自行修改** |

若一个现象同时包含多类问题，拆分处理。例如“价格太高导致要多玩两小时”是 `REVIEW-NUM/UX`；“合法玩家永远无法获得支付所需资源”是功能硬阻断，可进入修复流程。是否“更容易、更快、更爽”本身不构成功能缺陷。

### 3.1 严重度

- P0：不可恢复数据/库存损失、隐私泄露、无限重复铸造或全体无法启动。
- P1：主循环硬阻断、持续崩溃/卡死、无安全恢复路径。
- P2：重要分支错误、可恢复的数据不一致、大面积语言或布局错误。
- P3：局部但真实的文案、视觉、反馈或兼容问题。

`REVIEW-NUM` 与 `REVIEW-UX` 仍可标严重度，但处置保持“待审阅”。

## 4. 每轮全面测试的强制准入

### 4.1 冻结测试对象

记录以下全部信息：分发渠道、产品版本、构建时间、Git SHA（若可得）、安装包 SHA-256、Steam Build ID/分支、操作系统、应用数据目录、Steam 账号类型、语言、时区、DPI。工作树包还必须保存 `git status --short` 和补丁指纹；工作树在执行期间发生变化则结果作废或另开批次。

### 4.2 审阅版本差异

以“上次已通过的冻结版本”为基线，按玩家可见风险分类变更：安装/升级、主循环、存档 schema、Steam 资产与云、Codex/Claude 适配、引导、工厂模式、窗口/托盘、语言、素材、性能。对每个变更决定：新增用例、删除过时用例、更新预期、提高回归级别或无需改动，并写理由。

禁止只按改动文件名挑测试。所有跨系统变更至少回归：启动、载入存档、主宠点击、后院进入、一次购买/孵化、一次融合可达性、退出重启。

### 4.3 审阅测试运力

记录本轮真实可用资源：

- 可用 OS/硬件/DPI/显示器/GPU；是否有 macOS、Linux 与低配机。
- 是否有正式安装包、Steam 测试分支、离线包、旧版本包。
- Steam 在线/离线账号、空库存/丰富库存账号、云存档双机条件。
- Codex/Claude 的“已安装、未安装、未登录、进程退出、日志不可读”条件。
- 桌面自动化、浏览器自动化、截图/OCR、录像、性能采样、网络故障注入是否可用。
- 可恢复测试存档：新玩家、首只宠、两只满级、待收蛋、待融合、丰富图鉴、工厂中局、云冲突。
- 时间预算与人工语言审校能力。

无法执行的层必须写 `BLOCKED-CAPACITY`，不得以低层证据代替通过。

### 4.4 更新用例集

完成差异与运力审阅后：

1. 标记本轮 `P0 冒烟`、`P1 变更回归`、`P2 全量矩阵`。
2. 为新增功能加入正常、边界、异常、恢复、重复输入、跨重启和多语言用例。
3. 删除用例必须记录被哪个新用例或产品决定取代。
4. 固化新的合法游玩存档检查点，不覆盖历史基线。
5. 冻结用例版本后才能开始执行。

## 5. 测试环境与矩阵

### 5.1 平台最低矩阵

| 维度 | 组合 |
| --- | --- |
| Windows | Windows 10、Windows 11；安装包与 Steam；WebView2 当前版/缺失或损坏恢复 |
| macOS | 当前支持的 Intel/Apple Silicon 至少各一；安全警告、开机启动、菜单栏/退出 |
| Linux | 至少 Ubuntu LTS；AppImage/deb、托盘、Wayland/X11（能获得时） |
| 显示 | 1920×1080@100/125/150/200%，1366×768，1280×720，最小窗口约束，多显示器负坐标 |
| 输入 | 鼠标、触控板、键盘、长按、按键连发、输入法、无障碍减少动态 |
| 网络 | 正常、离线、DNS 失败、高延迟、丢包、断开后恢复、Steam 单独不可达 |
| 时间 | 正常、跨午夜、时区切换、系统时间前跳/后跳、休眠/唤醒 |

### 5.2 语言矩阵

必须覆盖 21 种设置：`en`、`zh-Hans`、`zh-Hant`、`ja`、`ko`、`fr`、`de`、`es-ES`、`es-419`、`pt-BR`、`pt-PT`、`ru`、`it`、`pl`、`tr`、`uk`、`ar`、`th`、`vi`、`id`、`nl`。

- 简中和英文只作语义/布局基线，不能代表其他语言。
- 其余 19 种语言必须对“界面状态清单”逐页截图和视觉检查。
- 阿拉伯语必须单独覆盖 RTL、数字/货币、左右方向、混合英文专名和滚动条。
- 西班牙/拉美西语、巴西/葡萄牙葡语必须分别检查地区用词，不得视为同一翻译。
- 母语审校缺失时可用“语义回译 + 场景任务”发现问题，但结论标 `NEEDS-NATIVE-REVIEW`，不得宣称完整语言通过。

## 6. 状态、账号与安全

### 6.1 测试状态分层

每个破坏性用例在专用用户目录和测试账号执行：

1. 复制原始测试存档到只读基线目录并计算哈希。
2. 启动前复制到一次性运行目录。
3. 记录 Steam 库存和云三件套摘要。
4. 运行破坏操作。
5. 验证恢复、余额/宠物/材料不变量和备份。
6. 保留失败副本，销毁一次性运行目录。

不得在含真实价值物品的账号上做重复融合、库存冲突、云覆盖或清档测试。

### 6.2 必须保护的不变量

- 一次玩家动作最多产生一次结算；快速连点不会重复扣款、重复发奖或重复消耗 Steam 材料。
- 失败或取消不会吞金币、宠物、蛋、皮肤、图鉴记录或 Steam 物品。
- 异步状态在退出、崩溃、断网、重启后可解释并可恢复，不永久等待。
- 存档冲突处理保留可定位的备份；新版本存档不被旧版本静默降级覆盖。
- 无 Codex/Claude、无 Steam、无网络时，纯本地核心玩法仍可进入；依赖功能明确降级。
- 键盘充能只使用按键次数/短暂表现，不持久化、记录或发送实际字符。

## 7. 测试技术

### 7.1 玩家旅程

覆盖：安装 → 首次启动 → 强引导 → 首宠 → 点击打工/精力 → 后院移动 → 商店购买 → 孵化 → 切换陪伴 → 两宠满级 → 融合 → 收取高阶宠 → 图鉴/皮肤 → 工厂模式 → Steam/云/成就 → 退出重启/升级。

每条旅程至少跑三种玩家画像：

- 顺从玩家：严格按提示操作。
- 急躁玩家：跳过动画、连续点击、反复打开关闭、在转场中输入。
- 探索/破坏玩家：逆序操作、走向屏幕边缘、使用错误对象、切语言、断网、杀进程、改时间。

### 7.2 边界与破坏性输入

- 数量：0、1、上限−1、上限、上限+1、极大历史累计。
- 时间：倒计时前后 1 秒、跨日、休眠、时钟回拨、长期离线。
- 并发：双击/25 连点、键鼠同时、窗口隐藏时事件、两个应用实例、两台机器同账号。
- 生命周期：动作提交前、提交中、响应后未落盘、落盘后未上云四个点强退。
- 文件：缺失、空文件、截断、非法 JSON、只读、锁定、磁盘满、较新 schema、备份冲突。
- 网络：请求前断、响应丢失、超时后晚到、重连、重复响应。
- 内容：超长名称、Emoji、组合字符、RTL、换行、占位符、非法/超大 UGC 分享文本。

### 7.3 依赖降级

依赖组合至少包含：

| Codex | Claude | Steam | 网络 | 预期 |
| --- | --- | --- | --- | --- |
| 无 | 无 | 无 | 离线 | 本地核心玩法、存档和退出可用；依赖能力清楚禁用 |
| 有 | 无 | 无 | 在线/离线 | Codex 活动正常；Claude 缺失不报错 |
| 无 | 有 | 无 | 在线/离线 | Claude 活动正常；Codex 缺失不报错 |
| 有 | 有 | 无 | 在线 | 两来源不重复计数、不串项目 |
| 任意 | 任意 | 有但未登录/离线 | 任意 | 不冻结；库存/云/工坊显示可恢复错误 |
| 任意 | 任意 | 已登录 | 高延迟/中断 | 异步操作有状态、超时、重试与幂等恢复 |

端口测试必须包括“被普通进程占用”和“被 Windows 排除端口保留”两类；发布版若不需要端口，应证明这些占用不影响启动。开发启动器必须给出可操作错误或可配置备用端口。

## 8. 视觉与本地化检查

### 8.1 界面状态清单

每种非简中/英文语言至少覆盖：首启/引导每类卡片、主宠/菜单、设置、后院、商店、孵化、满级/精力耗尽、融合前置/等待/成功/失败、图鉴列表/详情/皮肤/导入、Steam 市场/离线/云冲突、工厂首次进入/阵容/班次/结算/商店/贷款/失败/继续、确认框/toast/系统通知/托盘菜单。

### 8.2 视觉判定

截图与实际交互同时检查：

- 文字裁切、重叠、溢出、异常缩放、滚动条、按钮/关闭入口是否可见可点。
- 窗口是否随内容调整且留在可见屏幕；多显示器、任务栏、DPI 改变后不跑出屏幕。
- 动画、粒子、手势和提示层不遮挡主操作，不截获点击。
- RTL 的布局、箭头、进度、数字、混合专名方向正确。
- 缺字方框、字体回退、组合字符断裂、异常行高。
- 100%、125%、150%、200% 缩放与最小支持分辨率。

任何自动“无溢出”断言都必须配合最终截图人工检查；仅 DOM 几何通过不能证明语义、可读性或美观。

### 8.3 语义与机翻变义

测试人员必须扮演只会目标语言的玩家，先隐藏中文/英文原文，仅凭译文完成任务，再做回译核对。重点检查：

- 主体、对象、动作、否定、条件、时间、剩余数量、方向、概率、费用、退款、每日上限。
- `left` 等多义词在“剩余/左边”中的场景区别。
- “融合、孵化、陪伴、放生、结算、贷款、掉落、认领”等玩法词是否一致。
- Codex、Claude、Steam、Token、KPI 等专名不被错误翻译。
- 幽默、拟声和梗是否在目标地区可理解，不能因机翻变成攻击、性暗示或相反含义。
- 占位符、数字、货币、复数、语序在真实动态值下仍正确。

发现一个语义错误时，必须搜索同一概念在 21 种语言、所有运行时包和同屏上下文中的表现；不得只修截图中的一句。

## 9. 性能、耐久与资源

- 冷启动、稳定 10 分钟、2 小时、8 小时、休眠/唤醒、退出后进程/钩子释放。
- 0/1/上限宠物，200 个工厂角色，密集粒子、大风、减少动态。
- CPU、工作集、GPU、句柄、线程、磁盘写入、输入延迟、帧时间、长任务。
- 网络/Steam 长时间离线重试不得高频占用或无限增长日志/队列。
- 多次打开关闭面板、切语言、进出工厂、换皮肤后资源应回落，不持续单调增长。

性能阈值必须在首轮基线采样后由负责人确认。测试可立即修复明确的泄漏、卡死或输入失效；“希望更流畅”的主观目标归 `REVIEW-UX`。

## 10. 执行顺序与停止条件

1. 准入与备份。
2. P0 安装/启动/载入/退出冒烟。
3. 新玩家到首次融合的主旅程。
4. 变更面回归。
5. 依赖降级、存档/云/库存破坏性测试。
6. 21 语种视觉与语义矩阵。
7. 工厂、图鉴、皮肤、Steam 长路径。
8. 性能与耐久。
9. 修复后复测、全局冒烟和报告。

出现 P0、真实价值账号风险、不可恢复存档丢失、隐私泄露或重复 Steam 消耗时立即停止相关矩阵，冻结证据与副本，先修复或隔离后再继续。

## 11. 证据与结果标准

每条用例必须记录：用例 ID、构建指纹、环境、初始存档/库存摘要、实际步骤、期望、实际、结果、时间戳、截图/录像/日志路径、缺陷 ID、恢复结果。

结果仅允许：

- `PASS`：在指定层和环境真实通过。
- `FAIL-FIX`：应修复缺陷。
- `REVIEW-NUM`：数值问题，待审阅。
- `REVIEW-UX`：体验问题，待审阅。
- `BLOCKED-CAPACITY`：缺设备/账号/工具/权限，未验证。
- `NOT-APPLICABLE`：经版本差异审阅确认不适用并写理由。

不能把“未复现”“脚本通过”“浏览器通过”写成原生正式包 `PASS`。修复关闭需附：原失败证据、修复包指纹、原用例复测、相邻回归和状态恢复证明。

## 12. 完成标准

一轮“全面测试完成”必须同时满足：

- 版本差异与运力审阅已归档，用例集已更新。
- 所有 P0/P1 用例已执行，无未解决 `FAIL-FIX`。
- P2/P3 未执行项均有明确 `BLOCKED-CAPACITY` 和补测计划。
