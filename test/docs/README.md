# Gulugulu 全面黑盒测试文档

本目录是可重复执行的项目级测试基线。测试人员应假定拿不到产品源码，只能使用安装包、玩家可见界面、操作系统能力、Steam 客户端、Codex/Claude 的正常用户入口以及预先通过合法游玩形成的测试存档。

## 文档顺序

1. [00-全面黑盒测试规格.md](00-全面黑盒测试规格.md)：长期有效的范围、方法、缺陷分流、证据标准和每轮执行门禁。
2. [01-当前版本测试准入-2026-08-07.md](01-当前版本测试准入-2026-08-07.md)：当前工作树的版本差异、现有测试运力、缺口和本轮用例调整决定。
3. [02-当前版本玩家行为测试用例.md](02-当前版本玩家行为测试用例.md)：绑定当前版本风险面的玩家行为、边界、破坏性、依赖降级、本地化和视觉用例。
4. [03-全面测试执行记录模板.md](03-全面测试执行记录模板.md)：以后每次全面测试必须复制填写的准入、执行、缺陷与复测记录。

## 强制规则

- 每次全面测试前先做“版本差异 + 测试运力”审阅；未完成不得直接复跑旧用例。
- 黑盒发现阶段禁止通过阅读源码解释或放宽结果；修复阶段可以定位实现，但修复后必须重新以安装包黑盒复测。
- 功能、稳定性、数据安全、依赖降级、本地化语义和界面破版问题进入“发现即修”流程。
- 数值合理性与体验顺畅度只记录，不修改，等待项目负责人审阅。
- 浏览器组件测试、脚本断言和源码级单元测试只能作补充证据，不能替代 Tauri 原生窗口、托盘、Steam、全局键盘输入和真实存档的玩家测试。
- 破坏性测试只允许在一次性测试账号、隔离用户目录和可恢复备份上执行，不得伤害真实 Steam 库存或玩家存档。
